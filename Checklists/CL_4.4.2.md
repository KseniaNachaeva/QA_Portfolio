# CHECKLIST-4.4.2: Smoke-тестирование выбора кредитного предложения

**Модуль:** Выбор предложения (POST /application/apply)  
**Приоритет:** High  
**Тип тестирования:** Функциональное, smoke-тестирование  

## Предусловия
- Микросервис Application запущен и доступен по адресу http://localhost:8080
- БД доступна, микросервисы Deal и Dossier доступны, Kafka запущена
- Успешно выполнен шаг 1 из CHECKLIST-4.4.1, получен `applicationId` и список из 4 предложений

## Шаги воспроизведения

| № | Шаг | Данные | Ожидаемый результат |
|---|-----|--------|---------------------|
| 1 | Выполнить вызов метода POST /application/apply с выбранным предложением №1 | **URL:** http://localhost:8080/application/apply**Body:**```{  "applicationId": <applicationId>,  "requestedAmount": 100000,  "totalAmount": 100000,  "term": 24,  "monthlyPayment": 4500.00,  "rate": 15.0,  "isInsuranceEnabled": false,  "isSalaryClient": false}``` | Метод вызван, возвращен HTTP 200 OK, тело ответа пустое |
| 1.1 | Убедиться, что статус заявки изменился на APPROVED | **SQL:**```SELECT status FROM application WHERE id = <applicationId>``` | status = 'APPROVED' |
| 1.2 | Убедиться, что выбранное предложение сохранено в поле applied_offer | **SQL:**```SELECT applied_offer FROM application WHERE id = <applicationId>``` | Поле IS NOT NULL, содержит валидный JSON, идентичный отправленному Body |
| 2 | Повторно выполнить вызов POST /application/apply с теми же данными | **URL:** http://localhost:8080/application/apply**Body:***(тот же JSON, что и в шаге 1)* | Возвращен HTTP 500 с кодом ошибки ERR_1, дубликат записи в БД не создан |

## Фактический результат
Все проверки пройдены успешно

## Примечание
Этот чек-лист проверяет корректность фиксации выбранного оффера и идемпотентность операции. Он гарантирует, что:
- Данные предложения корректно маппятся в БД (маппинг T_03).
- Система защищена от повторной отправки одного и того же запроса (защита от дублирования статусов и записей).
