# BUG-04: Нарушение целостности БД: создание дубликата записи при повторном скоринге заявки со статусом CC_APPROVED

**Модуль:** Скоринг заявки (PUT /application/registration)  
**Критичность:** Major  
**Приоритет:** High  
**Тип тестирования:** Функциональное, целостность данных, идемпотентность  

## Предусловия
- Микросервис Application запущен и доступен по адресу http://localhost:8080
- БД доступна, микросервисы Deal, Conveyor и Dossier доступны
- Выполнен полный цикл до статуса `CC_APPROVED`:
  1. POST /application
  2. POST /application/apply (статус → APPROVED)
  3. PUT /application/registration/{applicationId} с валидными данными (первичный скоринг, статус → CC_APPROVED)

## Шаги воспроизведения

| № | Шаг | Данные | Ожидаемый результат |
|---|-----|--------|---------------------|
| 1 | Повторно вызвать метод скоринга с теми же данными | **URL:** http://localhost:8080/application/registration/{applicationId}**Body:** (те же валидные данные, что и в предусловии) | Метод вызван |
| 2 | Проверить количество записей в таблице `credit` | **SQL:**```SELECT COUNT(*) FROM credit WHERE application_id = <applicationId>``` | HTTP статус 500 с кодом `ERR_1`.В БД: `COUNT(*)` = 1 (дубликат не создан, статус заявки не меняется) |

## Фактический результат
Тест не пройден. HTTP статус 200 OK. В таблице `credit` появляются 2 записи (дубликат), связанные с одним `application_id`.

## Примечание
**Бизнес-ценность:** Нарушение принципа идемпотентности и целостности данных.
