# BUG-02: Подменённые данные LoanOfferDTO принимаются и записываются в БД (отсутствует проверка целостности)

**Модуль:** Выбор предложения (POST /application/apply)  
**Критичность:** Critical  
**Приоритет:** High  
**Тип тестирования:** Безопасность (Security), целостность данных  

## Предусловия
- Микросервис Application запущен и доступен по адресу http://localhost:8080
- БД, микросервисы Deal и Dossier доступны
- Выполнен успешный вызов POST /application, получены `applicationId` и список из 4 предложений
- Сохранены оригинальные данные первого предложения (например, `rate`: 15.0, `totalAmount`: 100000)

## Шаги воспроизведения

| № | Шаг | Данные | Ожидаемый результат |
|---|-----|--------|---------------------|
| 1 | Выполнить вызов POST /application/apply с **подменёнными данными** (изменить `rate` с 15.0 на 5.0 и `totalAmount` со 100000 на 50000) | **URL:** http://localhost:8080/application/apply**Body:**```{  "applicationId": <applicationId>,  "requestedAmount": 100000,  "totalAmount": 50000,  "term": 24,  "monthlyPayment": 2000.00,  "rate": 5.0,  "isInsuranceEnabled": false,  "isSalaryClient": false}``` | Метод вызван |
| 2 | Проверить состояние БД (таблица application) | **SQL:**```SELECT status, applied_offer FROM application WHERE id = <applicationId>``` | `status` = 'PREAPPROVAL' (не изменился)`applied_offer` IS NULL (подменённые данные не сохранены) |

## Фактический результат
Тест не пройден. HTTP статус 200 OK. Подменённые данные (`rate`: 5.0, `totalAmount`: 50000) успешно записаны в поле `applied_offer`, статус заявки изменён на `APPROVED`.

## Примечание
**Бизнес-ценность:** Критическая уязвимость безопасности (Data Tampering). Злоумышленник может перехватить запрос и изменить условия кредита в свою пользу (снизить ставку с 15% до 5% и сумму долга в 2 раза). Система одобрит заявку на выгодных для мошенника условиях, что приведёт к прямым финансовым потерям банка. Сервер обязан сверять хэш или значения пришедшего DTO с оригиналом из БД.
