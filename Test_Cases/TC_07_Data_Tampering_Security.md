# TC-4.4.2-SEC-04: Проверка целостности данных (защита от подмены кредитного предложения)

**Модуль:** Получение выбранного кредитного предложения (POST /application/apply)  
**Приоритет:** High  
**Тип тестирования:** Безопасность (Security Testing), целостность данных  

## Предусловия
- Микросервис Application запущен и доступен по адресу http://localhost:8080
- БД, микросервисы Deal и Dossier доступны, Kafka доступна
- Выполнен успешный вызов POST /application, получены `applicationId` и список из 4 кредитных предложений
- Сохранены оригинальные данные первого предложения (например, `rate`: 15.0, `totalAmount`: 100000)

## Шаги воспроизведения

| № | Шаг | Данные | Ожидаемый результат |
|---|-----|--------|---------------------|
| 1 | Выполнить вызов метода POST /application/apply с **подмененными данными** (изменить `rate` с 15.0 на 5.0 и `totalAmount` со 100000 на 50000) | **URL:** http://localhost:8080/application/apply**Body:**```{  "applicationId": "<applicationId>",  "requestedAmount": 100000,  "totalAmount": 50000,  "term": 24,  "monthlyPayment": 2000.00,  "rate": 5.0,  "isInsuranceEnabled": false,  "isSalaryClient": false}``` | Метод вызван |
| 2 | Проверить HTTP-статус ответа | — | HTTP статус 500 (или 400), тело ответа содержит код ошибки ERR_1 |
| 3 | Проверить логи МС Deal и Dossier | — | В логах МС Deal присутствует stack trace, указывающий на несоответствие переданных данных сгенерированному предложению. Вызов МС Dossier **НЕ производился** |
| 4 | Проверить состояние БД (таблица application) | **SQL:**```SELECT status, applied_offer FROM application WHERE id = <applicationId>``` | status = 'PREAPPROVAL' (не изменился на APPROVED)applied_offer IS NULL (подмененные данные не сохранены) |

## Фактический результат
**Тест НЕ пройден (найден Critical баг).**  
Система приняла подмененные данные, записала заниженную ставку (`5.0`) и сумму (`50000`) в поле `applied_offer`, а статус заявки изменился на `APPROVED`. Проверка целостности на стороне сервера отсутствует.  
*Заведен баг-репорт: Bug-4.4.2-07*

## Примечание
Этот тест проверяет **защиту от подмены данных (Data Tampering)**. В реальном приложении злоумышленник мог бы перехватить запрос и получить кредит на 100 000 ₽, но заплатить банку только 50 000 ₽ по ставке 5% вместо 15%. 

Сервер обязан сверять переданный `LoanOfferDTO` с тем, который был изначально сгенерирован и сохранен в БД, а не слепо доверять данным, пришедшим от клиента.
